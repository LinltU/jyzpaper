# 当前数据精准预测与异常预警方案报告（2026-08-05）

## 1. 结论先行

本工程当前已经具备“当前环境下测量电压精准估计”的基础能力，但“异常预警”还不应做成传统有监督分类模型。原因是：目前真实挂线数据中没有足够明确的异常标签，只有一场实验室异常测试。如果直接用这一场实验室异常训练分类器，模型会高度依赖该实验条件，难以保证现场泛化。

建议采用以下路线：

- 正常状态概率预测模型。
- 按设备、湿度阶段和湿度过程校准的残差阈值。
- 连续性与同串联动规则。
- 实验室异常事件作为外部验证，而不是作为大规模训练标签。

当前最佳预测基线仍是 25% DDPM 扩散增强候选。尾部风险融合版本 MAE 更低，但 RMSE 和区间覆盖率略低，因此暂不替换当前候选。

## 2. 当前目标与现实约束

### 2.1 业务目标

用户当前目标可以拆分为两层：

1. 精准预测当前采集数据对应的合理测量电压。
2. 当实测电压相对当前温湿度、安装位置和历史趋势明显异常时，及时预警。

这里的“异常”不应简单理解为数值大或小，而应理解为：在相同设备、相近温湿度、相近位置和相近历史趋势下，当前实测 Measure 明显偏离模型认为合理的正常范围。

### 2.2 数据约束

| 项目 | 数量 |
|---|---:|
| 历史 training.csv | 1,963 |
| 历史 test.csv | 421 |
| 最新 Excel 采集记录 | 8,851 |
| 合并后总记录 | 11,235 |
| 设备数 | 25 |
| 训练记录 | 9,520 |
| 真实在线留出测试记录 | 1,715 |

数据时间范围为 2025-11-12 11:00:29 至 2026-07-16 11:00:31。留出方式为逐设备时间尾部切分，不是随机打乱切分，更接近真实上线后的时间外推场景。

当前关键限制：

- 真实挂线数据基本可视为正常或弱异常数据，没有稳定、明确、可标注的大量异常样本。
- 只有一场实验室异常，不能支持训练复杂异常分类器。
- 实验室异常与现场挂线异常的湿度、污染、安装、外部电压扰动条件可能不同。
- 极高湿阶段样本多，但波动也最大，误报风险最高。

因此异常预警必须以“正常状态建模”为主，而不是直接做“异常/正常二分类”。

## 3. 当前预测模型能力

### 3.1 当前有效模型结构

当前工程已经形成以下预测链路：

1. 输入 24 条同设备历史记录。
2. 构建无 Battery 的特征工程。
3. 进入共享时序 FMLP 编码器。
4. 通过干燥、过渡、高湿、极高湿四阶段专家输出残差修正。
5. 输出 P10、P50、P90 三个分位数。
6. 在线阶段按 Hum 80 阈值路由到普通湿度模型或高湿专家。

其中：

- P50 表示当前条件下的期望测量电压。
- P10-P90 表示模型估计的主要正常波动区间。
- Actual - P50 是后续异常评分的核心残差。
- P90 - P10 表示模型对当前环境不确定性的估计。

### 3.2 Battery 处理结论

Battery 是测量设备电量，不是绝缘子的测量电压或物理驱动变量。当前正式候选模型和扩散生成器均不使用 Battery。

当前模型使用的替代信息包括：

- DeviceElapsedDays：设备运行时间代理变量。
- 设备 one-hot 或设备 embedding。
- 安装位置解析字段。
- 温湿度、绝对湿度、采样间隔和动态变化率。
- 高湿持续时间、湿度上升/下降标记。

### 3.3 最新在线回放结果

| 模型 | 整体 RMSE | 整体 MAE | R2 | 总覆盖率 | 极高湿 RMSE | 极高湿 MAE | 极高湿覆盖率 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 25% DDPM 扩散候选 | 0.214958 | 0.120976 | 0.423916 | 81.46% | 0.230589 | 0.144520 | 85.14% |
| 尾部风险条件残差融合 | 0.216130 | 0.117343 | 0.417619 | 80.76% | 0.232574 | 0.137905 | 83.86% |

结论：

- 如果优先考虑 RMSE、大误差和区间覆盖率，当前仍应以 25% DDPM 作为候选基线。
- 如果优先考虑 MAE 和典型误差，尾部风险融合更好。
- 由于异常预警更怕大误差漏报和区间失真，建议异常预警阶段仍以 25% DDPM 作为默认预测模型。

## 4. 当前异常判断逻辑的问题

当前 humidity_stage_ensemble_predictor.py 中的异常判断逻辑是：如果 Actual 不在 P10-P90 内，则 IsAnomaly 为 True。

这对离线诊断有用，但不适合作为最终现场报警规则。原因是：

- P10-P90 理论目标覆盖率约为 80%。
- 即使所有数据都正常，也可能约有 20% 样本落在该区间外。
- 高湿阶段天然波动大，单点越界更容易出现。
- 如果直接把 P10-P90 外部当作报警，会造成误报偏多。

因此，P10-P90 应该用于“风险评分基础”，而不是最终报警阈值。

## 5. 推荐异常预警框架

### 5.1 核心思想

用正常数据训练模型，让模型回答：在当前设备、位置、温度、湿度和历史趋势下，Measure 应该落在哪个范围？

再根据实测值偏离程度打分：

- Residual = Actual - P50。
- IntervalHalfWidth = max((P90 - P10) / 2, epsilon)。
- NormalizedScore = abs(Actual - P50) / IntervalHalfWidth。

这个分数越大，表示当前值越不像正常状态。

### 5.2 阶段化阈值

由于低湿和高湿波动差异极大，阈值必须分阶段设定：

| 阶段 | 条件 | 建议阈值来源 |
|---|---|---|
| dry | Hum < 50 | 真实验证集 dry 残差分位数 |
| transition | 50 <= Hum < 65 | 真实验证集 transition 残差分位数 |
| humid | 65 <= Hum < 80 | 真实验证集 humid 残差分位数 |
| very_humid | Hum >= 80 | 真实验证集 very_humid 残差分位数 |

同时建议增加过程状态：

| 过程 | 定义方向 | 原因 |
|---|---|---|
| 湿度快速上升 | HumRate > 0 且超过阶段阈值 | 最容易出现测量突变 |
| 持续高湿 | HoursAbove80 较大 | 波动大但可能是正常高湿状态 |
| 湿度回落 | HumRate < 0 | 残差方向可能不同 |
| 低湿稳定 | Hum 低且 HumMAD6 小 | 应使用更敏感阈值 |

最终阈值不应是全局一个数字，而应逐步演进为：设备或设备组、湿度阶段、湿度过程三维阈值。

## 6. 推荐预警等级

建议把原来的二值异常改成四级：

| 等级 | 名称 | 触发条件建议 | 处理方式 |
|---|---|---|---|
| L0 | 正常 | 分数低于关注阈值 | 正常显示 |
| L1 | 关注 | 单点超出 P10-P90 或超过验证集 P90 残差 | 记录，不强报警 |
| L2 | 预警 | 超过阶段 P97.5 阈值，或连续 2 点 L1 | 界面黄色，提示复核 |
| L3 | 报警 | 超过阶段 P99 阈值，或连续 3 点 L2，或同一串多设备同步异常 | 界面红色，建议现场检查 |

这样可以避免单点噪声造成频繁报警，同时保留异常持续扩大时的触发能力。

## 7. 实验室异常数据的正确用法

当前只有一场实验室异常，不建议直接加入训练集训练异常分类器。

正确用法是：

- 训练：只用真实挂线正常或近正常数据。
- 阈值：只用真实训练和验证残差分布。
- 验证：用实验室异常事件做外部压力测试。

### 7.1 建议整理格式

建议把实验室异常整理为独立目录：

- dist2026/lab_anomaly_events/event_001.csv
- dist2026/lab_anomaly_events/event_001_metadata.json

event_001.csv 建议字段：

| 字段 | 含义 |
|---|---|
| IMEI | 设备编号 |
| Timestamp | 时间 |
| Measure | 测量电压 |
| Temp | 温度 |
| Hum | 湿度 |
| Location | 安装位置 |
| InputVoltage | 实验输入电压或施加条件 |
| EventStage | normal_before / anomaly / recovery |
| EventLabel | normal / anomaly |
| Note | 实验说明 |

event_001_metadata.json 建议记录：

- event_id。
- source，例如 lab。
- anomaly_type。
- start_time 和 end_time。
- device。
- line_voltage_kv。
- 实验条件、输入电压、湿度条件和异常机理说明。

### 7.2 应输出的验证指标

用当前模型跑实验室异常事件，重点不是 RMSE，而是：

| 指标 | 含义 |
|---|---|
| DetectionDelay | 异常开始后多久触发 L2/L3 |
| TrueAlarmRate | 异常段中有多少比例被预警或报警 |
| FalseAlarmBeforeEvent | 异常前正常段误报次数 |
| RecoveryDelay | 异常解除后多久恢复正常 |
| MaxAnomalyScore | 异常段最高分数 |
| ScoreSeparation | 异常段分数与正常段分数的分离度 |

如果实验室异常不能显著拉高 NormalizedScore，说明当前模型还缺少对应故障机理特征，而不是简单调阈值能解决。

## 8. 是否需要扩散模型生成异常数据

不建议当前直接用扩散模型生成异常训练集并训练报警分类器。

原因：

1. 扩散模型当前学习的是正常高湿波动，不是真实故障机理。
2. 只有一场实验室异常，不足以让生成模型学到异常分布。
3. 生成异常如果不符合物理机理，可能让报警器学到错误边界。
4. 合成异常可以用于压力测试，但不应作为真实异常标签训练核心模型。

可以做的方向是基于实验室异常形态做半合成压力测试：

- 正常序列叠加实验室异常残差模板。
- 正常序列叠加突变幅度扫描。
- 正常序列叠加持续漂移扫描。
- 正常序列叠加恢复过程扫描。

这类数据用于测试阈值灵敏度，而不是替代真实异常样本。

## 10. 当前推荐部署策略

### 10.1 短期

短期目标不是上线自动故障诊断，而是上线异常辅助预警：

- 模型预测：25% DDPM 候选。
- 报警阈值：正常验证集残差分位数。
- 报警规则：分阶段阈值 + 连续性确认。
- 实验室异常：只作为外部验证。

短期可交付：

1. 异常评分模块。
2. 阈值标定脚本。
3. 实验室异常回放报告。
4. GUI 显示 L0-L3 预警等级。

### 10.2 中期

中期目标是积累真实挂线异常或人工复核标签。每次 L2/L3 触发后，人工标注：真异常、环境正常波动、采集异常、设备异常或不确定。

有了几十到上百个复核样本后，可以训练轻量二阶段模型，输入 NormalizedScore、Residual、Hum、HumRate、HoursAbove80、同串其他设备分数和历史连续异常次数，输出真实异常概率。

### 10.3 长期

长期如果要真正实现提前预警，还需要扩展为未来温湿度预测、未来 Measure 概率预测和异常风险提前量评估。

当前模型使用目标时刻温湿度，因此更适合当前状态评估，不是完整的提前数小时预测系统。

## 11. 风险与注意事项

1. 只有一场实验室异常，不能证明模型对所有现场异常有效。
2. 极高湿阶段正常波动大，单点残差报警容易误报。
3. 实验室异常的机理如果与现场污染、受潮、老化不同，阈值验证可能乐观或悲观。
4. 扩散生成的异常不能替代真实异常标签。
5. 预警系统上线后必须记录每次报警和人工复核结果，否则无法持续改进。
6. 当前 P10-P90 区间不是最终报警区间，需要另行标定 P97.5、P99 等更高阈值。
7. GUI 默认生产 manifest 尚未切换到最新扩散候选，若要用于新预警模块，需要明确选择 manifest。

## 12. 下一步执行清单

建议按以下顺序推进：

1. 建立 anomaly_scoring.py，把残差、分数、等级、原因统一输出。
2. 建立 calibrate_anomaly_thresholds.py，只用训练文件内部真实验证尾部标定阈值。
3. 建立 lab_anomaly_events 目录规范，让实验室异常数据可回放。
4. 建立 evaluate_lab_anomaly_event.py，输出实验室异常检测延迟和误报指标。
5. 修改 GUI 展示，从二值正常/异常升级为 L0-L3。
6. 先离线比较 25% DDPM 与尾部风险融合在实验室异常上的触发能力，再决定是否切换预警模型。
7. 上线后保存每次 L2/L3 事件和人工复核结果，形成后续监督学习数据集。

## 13. 最终建议

当前工程已经适合做“正常状态概率预测 + 半监督异常预警”，不适合直接做“异常分类模型”。

最稳妥的工程路线是：继续使用当前最优预测模型，用正常验证残差建立分阶段阈值，用实验室异常检验触发能力，上线低风险 L0-L3 辅助预警，并在积累真实复核标签后再训练异常分类器。
