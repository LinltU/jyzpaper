# FMLP 算法优化过程报告

## 1. 报告信息

- 工程：绝缘子设备数据管理与预测系统
- 优化对象：FMLP、FMLP-LTSF、湿度阶段预测模型
- 训练数据：`training.csv`
- 测试数据：`test.csv`
- 评测日期：2026-07-13
- Python 环境：Python 3.8.20，PyTorch 1.x，CPU

## 2. 优化目标

本次优化主要解决以下问题：

1. 原 FMLP 的序列分解作用在长度为 1 的伪序列上，季节项恒接近 0。
2. 原 FMLP-LTSF 虽然输入 52 个特征，但最终只保留第一个通道，而第一个通道实际是 `Hour`，温湿度和历史测量特征没有真正参与输出。
3. 训练和预测的特征维度、顺序及目标通道不统一。
4. 数据集按全表切分，没有保证每台设备内部的时间顺序。
5. 低湿度趋势平稳，而高湿度尤其 `Hum >= 80%` 时波动显著增大，单模型难以同时拟合各阶段。
6. 原系统只输出单点预测，不能表达高湿度阶段明显增加的不确定性。

最终目标是实现：

```text
共享时序编码器
    + 四个湿度阶段残差专家
    + 平滑湿度门控
    + P10/P50/P90 分位数输出
```

## 3. 数据分析

### 3.1 数据规模

| 数据集 | 行数 | 设备数 | 每设备样本数 | 时间范围 |
|---|---:|---:|---:|---|
| training.csv | 1,963 | 25 | 66-85 | 2025-11-12 至 2026-01-06 |
| test.csv | 421 | 25 | 10-28 | 2025-11-12 至 2026-01-06 |

训练集和测试集时间范围高度重叠，测试集不是严格意义上的未来时间段，更接近同一时间范围内抽出的测试点。因此本次采用滚动一步预测：使用同设备此前 24 条记录预测下一条 `Measure`。

经过历史窗口构造后：

- 训练序列：1,144
- 验证序列：219
- 测试序列：320
- 输入特征：46
- 输入长度：24
- 预测长度：1

### 3.2 湿度阶段差异

按照 `<50%`、`50-65%`、`65-80%`、`>=80%` 划分：

| 湿度阶段 | 样本数 | Measure 均值 | Measure 标准差 | 相邻变化中位数 |
|---|---:|---:|---:|---:|
| `<50%` | 638 | 0.090 | 0.075 | 0.0065 |
| `50-65%` | 892 | 0.146 | 0.128 | 0.0338 |
| `65-80%` | 706 | 0.281 | 0.199 | 0.0853 |
| `>=80%` | 148 | 0.669 | 0.376 | 0.3671 |

主要结论：

- `Hum >= 80%` 时，相邻变化中位数约为低湿度的 56 倍。
- 极高湿度下不仅测量均值上升，方差和变化速度也显著上升。
- 使用统一误差尺度或统一专家，会让低湿度和高湿度互相干扰。
- 极高湿度样本仅 148 条，不适合单独训练完整深度模型，更适合共享编码器上的小型残差专家。

## 4. 原算法问题

### 4.1 表格 FMLP 的伪序列分解

原 `model/fmlp.py` 将 `[Batch, Feature]` 转换为 `[Batch, 1, Feature]`，再使用移动平均分解。由于时间长度为 1：

```text
Trend ≈ Input
Seasonal ≈ 0
```

季节分支实际失效，模型退化为带冗余结构的普通 MLP。

### 4.2 FMLP-LTSF 丢弃外生变量

原实现对每个通道独立进行时间映射，最后执行：

```python
seasonal_output = seasonal_output[:, 0:1, :]
trend_output = trend_output[:, 0:1, :]
```

由于第一个特征是 `Hour`，原模型接近于：

```text
过去 24 个 Hour -> 未来 Measure
```

温度、湿度、绝对湿度、位置和其他通道基本没有影响最终预测。

### 4.3 数据与指标问题

- 目标通道依赖固定索引，没有显式 `target_index`。
- 特征列表缺少原始历史 `Measure`。
- 全表按行切分可能把不同设备分配到不同集合。
- 表格模型预测标准化目标后，没有正确反标准化再计算指标。
- 多步指标使用预测均值与单点实际值对比，时间位置没有严格对齐。
- 原生产流程过滤 `Hum >= 80%`，导致风险最高区间只能外推。

## 5. 第一阶段优化：基础 FMLP 重构

### 5.1 表格 FMLP

文件：`model/fmlp.py`

改为真正的特征门控残差 MLP：

```text
LayerNorm
  -> Feature Gate
  -> Input Projection
  -> Residual MLP Block
  -> Linear Regression Head
```

关键变化：

- 删除长度为 1 时无效的序列分解。
- 保留特征门控机制。
- 使用残差连接提高训练稳定性。
- 删除 `Softplus` 输出限制，使模型能够拟合标准化后的负目标值。

### 5.2 多变量 FMLP-LTSF

文件：`model/fmlp_ltsf.py`

模型分成两个支路：

```text
目标历史 Measure -> 趋势/季节分解 -> 基础预测

全部动态及静态特征 -> 特征混合 -> 时间映射 -> 上下文预测

基础预测 + 上下文预测 -> 融合输出
```

关键变化：

- 增加显式 `target_index`。
- 所有外生通道先经过 `Linear(enc_in, hidden_dim)` 混合。
- 不再丢弃温度、湿度和设备属性。
- 移动平均核由 25 调整为 7，更适合 24 步输入窗口。
- 输出维度固定为 `[Batch, PredLen, 1]`。

### 5.3 训练管线

历史文件：`archive/legacy_code/train_unified.py`

改动包括：

- 把原始历史 `Measure` 加入特征，丰富特征由 52 维增加到 53 维。
- 每台设备分别按时间切分训练、验证和测试数据。
- 验证和测试集合保留训练边界前的历史上下文。
- 标准化器只拟合训练数据。
- 修复目标通道索引。
- 修复加权损失计算。
- 修复反标准化和多步评测对齐。

## 6. 第二阶段优化：固定数据集评测

文件：`evaluate_fmlp_fixed_split.py`

由于测试集中每台设备只有 10-28 条数据，不能稳定构造 24 步输入和 6 步连续测试目标，因此采用：

```text
过去 24 条设备记录 -> 下一条 Measure
```

特征包括：

- 历史 `Measure`
- `Temp`、`Hum`、`Battery`
- 绝对湿度 `AH`
- 采样间隔 `DeltaHours`
- 小时、星期、月份周期编码
- 9 个位置特征
- 25 个设备独热编码

### 6.1 绝对值预测结果

| 指标 | FMLP | 持久性基线 |
|---|---:|---:|
| RMSE | 0.2231 | 0.2401 |
| MAE | 0.1414 | 0.1374 |
| R² | 0.2729 | 0.1578 |

绝对值模型降低了大误差，但 MAE 没有改善。

### 6.2 残差预测

模型目标改为：

```text
Residual = Measure[t] - Measure[t-1]
Prediction = Measure[t-1] + PredictedResidual
```

结果：

| 指标 | 残差 FMLP | 持久性基线 | 改善 |
|---|---:|---:|---:|
| MSE | 0.0442 | 0.0577 | 23.4% |
| RMSE | 0.2102 | 0.2401 | 12.5% |
| MAE | 0.1319 | 0.1374 | 4.0% |
| R² | 0.3546 | 0.1578 | - |

残差学习使持久性预测成为稳定起点，模型只需要学习变化修正。

## 7. 第三阶段优化：四阶段湿度专家

### 7.1 模型结构

文件：`model/humidity_stage_fmlp.py`

```text
历史序列
   |
   v
共享 FMLP 时序编码器
   |
   +---------------- 全局分位数头
   |
   +-> 干燥专家       Hum < 50
   +-> 过渡专家       50 <= Hum < 65
   +-> 高湿专家       65 <= Hum < 80
   +-> 极高湿专家     Hum >= 80
              |
              v
       门控加权残差修正
              |
              v
          P10/P50/P90
```

共享编码器学习所有阶段的公共规律，四个专家只学习相对公共预测的残差修正，降低极高湿度小样本过拟合风险。

### 7.2 平滑门控

门控输入：

- 当前湿度
- 当前湿度相对上一时刻的变化量

使用 50%、65%、80% 三个边界构造平滑先验，再叠加可学习门控：

```text
Gate = Softmax(log(StagePrior) + 0.25 * LearnedGate)
```

这种方式避免湿度在边界附近轻微变化时模型输出突然跳变。

测试集平均门控权重：

| 实际阶段 | 对应专家平均权重 |
|---|---:|
| 干燥 | 85.4% |
| 过渡 | 75.6% |
| 高湿 | 80.6% |
| 极高湿 | 78.7% |

### 7.3 有序分位数输出

模型不直接输出三个互相独立的数，而是输出中位数和正间距：

```text
P50 = Median
P10 = Median - Softplus(LowerGap)
P90 = Median + Softplus(UpperGap)
```

因此模型结构上保证：

```text
P10 <= P50 <= P90
```

不会发生分位数交叉。

### 7.4 损失函数

使用三个分位数的 Pinball Loss：

```text
Quantiles = [0.1, 0.5, 0.9]
```

湿度阶段样本权重：

| 阶段 | 权重 |
|---|---:|
| 干燥 | 1.1 |
| 过渡 | 1.0 |
| 高湿 | 1.2 |
| 极高湿 | 2.4 |

同时加入：

- 专家残差 L2 正则，避免小样本专家过拟合。
- 门控与物理湿度先验的 KL 约束，避免专家路由完全失控。

### 7.5 分阶段区间校准

验证集采用 Conformal 校准：

- 干燥、过渡、高湿目标覆盖率：80%
- 极高湿目标覆盖率：90%
- 阶段验证样本少于 20 时，回退到全局校准边界。

## 8. 最终测试结果

### 8.1 总体结果

| 指标 | 四阶段 FMLP | 单模型残差 FMLP | 持久性基线 |
|---|---:|---:|---:|
| MSE | 0.00849 | 0.04418 | 0.05765 |
| RMSE | 0.09216 | 0.21020 | 0.24011 |
| MAE | 0.04750 | 0.13186 | 0.13738 |
| R² | 0.87592 | 0.35460 | 0.15781 |
| sMAPE | 22.89% | 61.51% | 52.12% |
| 中位绝对误差 | 0.02201 | 0.07597 | 0.06380 |

相对单模型残差 FMLP：

- RMSE 降低 56.2%。
- MAE 降低约 64.0%。
- R² 从 0.355 提升到 0.876。

### 8.2 分湿度阶段结果

| 湿度阶段 | 测试数 | RMSE | MAE | R² | P10-P90 覆盖率 | 平均区间宽度 |
|---|---:|---:|---:|---:|---:|---:|
| `<50%` | 71 | 0.02367 | 0.01689 | 0.87777 | 95.8% | 0.0963 |
| `50-65%` | 125 | 0.04990 | 0.03137 | 0.81060 | 96.0% | 0.1863 |
| `65-80%` | 99 | 0.06382 | 0.04537 | 0.92680 | 93.9% | 0.2305 |
| `>=80%` | 25 | 0.28027 | 0.22341 | 0.41205 | 76.0% | 0.6848 |

区间宽度随湿度阶段上升，符合高湿度波动增大的数据特性。

### 8.3 极高湿度改进

| 指标 | 四阶段 FMLP | 单模型 FMLP | 持久性基线 |
|---|---:|---:|---:|
| RMSE | 0.2803 | 0.5778 | 0.6217 |
| MAE | 0.2234 | 0.4921 | 0.5178 |
| R² | 0.4121 | -1.4990 | -1.8928 |

极高湿度阶段由负 R² 提升到正 R²，说明阶段专家确实学到了与低湿度不同的变化模式。

## 12. 当前限制

1. `training.csv` 和 `test.csv` 时间范围重叠，不是严格未来外推测试。
2. 极高湿度测试样本只有 25 条，指标置信区间较宽。
3. 极高湿度的目标区间覆盖率设为 90%，测试实际覆盖率为 76%，说明验证集和测试集在极高湿度阶段仍存在分布变化。
4. 当前门控使用目标时刻可观测的湿度和湿度变化率，适合实时状态评估；如果要提前预测未知未来，必须增加温湿度预测支路。
5. 四阶段模型尚未接入 PyQt GUI 和现有模型保存/加载流程。
6. 当前绝缘状态展示仍存在将分数强制映射到高分区间的问题，需要与分位数异常分数统一。

## 13. 后续建议

### 高优先级

1. 将四阶段模型接入 GUI 的模型选择、加载和在线预测流程。
2. 使用 P50 作为正常期望值，使用 P10-P90 区间计算异常分数。
3. 删除固定映射到 85-98 的绝缘程度规则。
4. 建立严格按时间的未来测试集，避免训练/测试时间重叠。

### 中优先级

1. 增加 `连续高湿时长`、`最近 6 点最大湿度`、`湿度上升/下降阶段`。
2. 对极高湿度阶段采集更多数据，目标至少 500 条以上。
3. 使用多随机种子或模型集成，提高极高湿度预测稳定性。
4. 增加设备维护、清扫、降雨和污染等级数据。

### 长期方向

1. 同时预测未来温湿度与 `Measure`，实现真正的提前预警。
2. 为每个阶段输出可解释的特征重要性和专家贡献。
3. 使用滚动校准更新分位数区间，适应季节和设备老化导致的分布漂移。

## 14. 结论

本次优化证明，湿度阶段之间的趋势和波动机制存在明显差异。共享编码器能够保留跨阶段公共信息，阶段残差专家能够学习各湿度区间特有的变化规律，分位数输出能够表达随湿度上升而增加的不确定性。

最终四阶段模型在现有测试协议下取得：

```text
RMSE = 0.0922
MAE  = 0.0475
R2   = 0.8759
```

相较单模型 FMLP，RMSE 降低 56.2%，并使极高湿度阶段 R² 从负值提升到 0.412。当前结果支持继续将四阶段模型作为系统新的主要预测算法，但正式上线前仍需要严格未来时间测试和 GUI 集成。
